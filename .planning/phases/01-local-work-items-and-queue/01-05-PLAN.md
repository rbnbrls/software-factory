<objective>
**As the** operator, **I want to** have every status change be one validated, atomic, recoverable operation, **so that** a crash never loses an item, duplicates it, or leaves me unable to tell what state it is in.

ROADMAP Phase 1 goal (verbatim): "The operator can safely define, approve, prioritize, and resume work from local Markdown."

Purpose: WF-04 requires validated transitions and atomic status/location updates. The design's whole crash story rests on "rename first, rewrite second, reconcile third" — this plan makes that the only mutation path and gives the operator the single repair command.
Output: `src/domain/transitions.ts`, hardened `atomic-file.ts`/`work-item-store.ts`, and `factory reconcile`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validation result → rename → rewrite | A two-step mutation with a visible intermediate state |
| filesystem → repair authority | Frontmatter content decides where a file belongs |
| CLI inspection → operator trust | Read commands must not silently change state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-16 | Tampering | rename/rewrite window (TOCTOU) | high | mitigate | Destination existence is checked immediately before `rename`; `rename` itself is the atomic step; a crash leaves a detectable mismatch that only `reconcile` repairs. No `access()`-then-`open()` pattern. |
| T-1-17 | Tampering | symlink at a work-item destination | medium | mitigate | `rename` replaces the directory entry instead of writing through a link; `writeFileAtomic` creates a fresh `wx` temp in the destination's directory and renames over it. |
| T-1-18 | Repudiation | silent mutation during inspection | high | mitigate | `reconcile` is the only repairer; `test/reconcile.test.ts` hashes the factory tree before/after `validate`, `queue`, `show`, `status` and requires equality. |
| T-1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install and no new dependency; the move uses `node:fs/promises` only. |
</threat_model>
