<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validation result → rename → rewrite | A two-step mutation with a visible intermediate state |
| filesystem → repair authority | Frontmatter content decides where a file belongs |
| CLI inspection → operator trust | Read commands must not silently change state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-16 | Tampering | rename/rewrite window (TOCTOU) | high | mitigate | Destination existence is checked immediately before `rename`; `rename` itself is the atomic step; a crash leaves a detectable mismatch that only `reconcile` repairs. No `access()`-then-`open()` pattern. |
| T-1-17 | Tampering | symlink at a work-item destination | medium | mitigate | `rename` replaces the directory entry instead of writing through a link; `writeFileAtomic` creates a fresh `wx` temp in the destination's directory and renames over it. |
| T-1-18 | Repudiation | silent mutation during inspection | high | mitigate | `reconcile` is the only repairer; `test/reconcile.test.ts` hashes the factory tree before/after `validate` and `queue` and requires equality, and plans 01-06/01-09 add the same proof for `show`/`status`. |
| T-1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install and no new dependency; the move uses `node:fs/promises` only. |
</threat_model>
