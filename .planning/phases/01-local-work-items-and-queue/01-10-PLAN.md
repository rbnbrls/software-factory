<objective>
**As the** operator, **I want to** interrupt the factory at any moment and be told exactly what happened and what to do next, **so that** I can resume the same run safely or record it as interrupted before any replacement starts.

Purpose: WF-07 and D-12. The resume-vs-replace decision is the phase's most dangerous path: a wrong "resume" duplicates side effects, a wrong "replace" loses the only evidence. This plan makes every crash residue classifiable and every decision recorded append-only.

    1. `idle` -> proceed.
    2. `active` / `held-alive` / `held-uncertain` -> refuse (exit 3).
    3. terminal run -> finalize (receipt + item transition as fixed in Task 1: `succeeded` → `blocked` + `needs-acceptance` with `acceptance: null`; `failed`/`needs-human`/`interrupted` → `blocked` + `needs-triage`; never `done`), release.
    4. item revision != run revision -> replace with reason `revision-changed`.
    5. probe `completed` -> append the missing terminal event, finalize.
    6. probe `not-started` -> resume with the SAME runId, append `run.resumed` with `previousLastType`.
    7. probe unknown/in-flight -> demo: replace with reason `unknown-side-effects`; a future runner: refuse `unsafe-resume` exit 3.
    `applyRecovery` performs the chosen action with the lease held, appending `run.interrupted` to the OLD run before any replacement directory is created.

    `src/commands/run.ts`: call reconcile, then `classifyRecovery` before `selectNext`; a `refuse` exits 3 with the classification in `data`; a `resume` continues the same run; a `replace` appends `run.interrupted` and starts `attempt+1` under a new runId. Then drain as before.

    `src/commands/resume.ts` and `src/commands/close.ts` share ONE lease protocol, implemented once as `withRunLease(paths, runId, mutate)` in `src/services/recovery.ts` and used by both — no command may mutate run or item state outside it:
    1. `classifyLease(...)`. Refuse with exit 3 `lease-held` and write nothing when the classification is `active`, `held-alive`, or `held-uncertain` (a live or ambiguous writer exists, whatever its `runId`).
    2. If a lease file exists whose `runId` differs from `runId` and the classification is not `idle`, refuse with exit 3 `run-unresolved` naming the other run — that run must be finalized first; never adopt or unlink it.
    3. `acquireLease` for `runId` when no lease exists (`EEXIST` -> `lease-held`, exit 3, no mutation). When the lease already belongs to `runId`, hold it read-only — do not rewrite it.
    4. Run `mutate()` with the lease held.
    5. In `finally`, call `releaseLease` ONLY when `readLease(paths)?.runId === runId`. A lease belonging to any other run is never unlinked; on a mismatch, report the leftover lease instead of releasing it.

    `src/commands/resume.ts`: `resumeCommand RUN_ID` requires `--yes` on a non-TTY, wraps the whole resume in `withRunLease(RUN_ID, ...)`, then re-runs the decision tree for that specific run — probe, `run.resumed`, continue the runner, terminal event, item transition, receipt. Refuses with `unsafe-resume` when the probe/owner/revision conditions are not met (nothing written). Releases the lease when the resumed run reaches a terminal state; a resumed run that is still open leaves the lease to expiry/recovery.

    `src/commands/close.ts`: `closeCommand RUN_ID --outcome interrupted|failed|abandoned` requires `--yes` on a non-TTY, refuses when the run is already terminal with a different outcome, and otherwise runs inside `withRunLease(RUN_ID, ...)`: append the terminal event (mapping `abandoned` -> `run.interrupted` with reason `operator-close`), write the receipt, move the item to `blocked` + `needs-triage` (never `done`), then release only the lease owned by `RUN_ID`.

    `src/commands/runs.ts`: list all runs sorted by startedAt then id (`{runId, workItemId, outcome, startedAt, endedAt}`) or replay one run's event timeline. Read-only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crash residue → recovery decision | On-disk state from a killed process decides whether work resumes |
| run log → history | Append-only evidence that must survive every recovery action |
| operator command → run outcome | Manual close/resume can end or continue work |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-32 | Tampering | corrupt or truncated run log | medium | mitigate | Reader ignores only a torn LAST line; any earlier malformed line is `run-log-corrupt` exit 2; the file is never rewritten to "fix" it. |
| T-1-33 | Elevation of Privilege | unsafe resume duplicating side effects | high | mitigate | Resume requires dead same-host owner + conclusive probe + unchanged revision; otherwise `run.interrupted` is appended and a new attempt starts; an inconclusive probe refuses with exit 3. |
| T-1-34 | Information Disclosure | run logs/artifacts | low | mitigate | Phase 1 run data contains IDs, revision, runner identity, timestamps, and a fixed sentence only; `close` and `resume` never print environment or credentials. |
| T-1-35 | Repudiation | operator close without a record | medium | mitigate | `close` appends a terminal event with reason `operator-close` and writes the receipt before blocking the item; the pre-close history is untouched. |
| T-1-42 | Tampering | `close`/`resume` releasing another run's lease | high | mitigate | Both commands run through `withRunLease`: it refuses on `active`/`held-alive`/`held-uncertain` and on a foreign non-idle `runId`, acquires before mutating, and unlinks only when `readLease()?.runId === runId`. A test seeds a live foreign lease and asserts both commands exit 3 with that lease byte-identical. |
| T-1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install and no new dependency. |
</threat_model>
