<objective>
**As the** operator, **I want to** accept or reject the result of a run as a separate, recorded human decision, **so that** no agent or demo runner can ever declare its own work accepted.

ROADMAP Phase 1 goal (verbatim): "The operator can safely define, approve, prioritize, and resume work from local Markdown."

Purpose: D-13 and project plan §11 — "checks, agent review, and human acceptance are separately recorded". The run ends when a human decision is needed and does not wait; the decision is a first-class, append-only record tied to the exact revision that ran.
Output: `factory accept` / `factory reject`, the acceptance service, and the proof that no automated path reaches `done`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run result → human decision | Automation produces evidence; only a human may accept it |
| acceptance record → item status | A recorded decision is the sole trigger for `done` |
| operator identity → audit | `decidedBy` is self-asserted on a single-user local system |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-36 | Elevation of Privilege | runner/automation self-asserting acceptance | high | mitigate | There is no code path from a runner result to `done`; `accept` is the only caller of `blocked -> done`, requires a succeeded awaiting run and an operator confirmation; a test greps that `run.ts`/`reconcile.ts` never write `done`. |
